WAREHOUSE — FINAL MANAGER-CREATED DELIVERY + INSTALLATION WORKFLOW (NOV 2026)

WHO DOES WHAT:
1. Manager alone creates an order: destination, date, customer/recipient, service type (Delivery only OR Delivery + installation), assigned delivery staff and each product with a quantity ONLY. No serial selection in the manager form. Every product dropdown shows current AVAILABLE quantity (including 0).
2. Employee opens assigned order and searches for matching serial numbers as soon as they type a letter or number. They must choose exactly the manager-required quantity for each product.
3. Employee submits serials, status is Pending manager approval. Manager receives an in-app notification and can Approve or Reject. On rejection, serials are released and employee can correct and resubmit.
4. ONLY after manager approval can employee upload evidence. ALL orders require a signed delivery document (PDF or image); DELIVERY + INSTALLATION also requires 1–6 installation photos.
5. After successful upload the order AUTOMATICALLY becomes Completed (no additional manager click). The delivered stock is deducted. Manager receives an in-app completion notification and can view the evidence.

DESIGN: Original dark teal/black WAREHOUSE design and colors preserved from your initial repository; no redesign or new theme.

SUPABASE: Database migrations already applied to Trade. Do NOT rerun schema.sql or any old migration. Trade data/inventory were not intentionally modified. Files uploaded during a failed submission might stay in Supabase Storage even if an order did not complete.

DEPLOY GITHUB PAGES:
1. Extract this ZIP.
2. Replace only index.html, app.js, styles.css, config.js in the ROOT of the existing Wearhouse GitHub repository.
3. Commit to the GitHub Pages branch; hard refresh the site or reopen in private browsing.
4. Log in as manager, open Delivery / Installation > + New delivery order.
5. Test one small order as both manager and delivery employee.

NOTES: In-app notifications (not email/push). Previous legacy delivery requests remain visible separately for reference. No new requests can be created through the old employee-initiated workflow.
